RELATÓRIO TEÓRICO: DESENVOLVIMENTO DE APLICAÇÃO FRONT-END COM CONSUMO DE API

Disciplina: Desenvolvimento Web Front-End • Tecnologias: HTML5, CSS3, JavaScript Puro (Vanilla) • API: The Rick and Morty API

1. O que é uma API e como funciona o consumo de dados em tempo real

Uma API (Application Programming Interface) é uma interface que estabelece contratos, protocolos e ferramentas para a comunicação entre sistemas heterogêneos. Na web, o modelo predominante é a API RESTful, fundamentada no protocolo HTTP/HTTPS, transmitindo cargas de dados codificadas em formato JSON (JavaScript Object Notation).

O consumo em tempo real funciona por meio de um ciclo estruturado de comunicação assíncrona:

  • Requisição (Request): O navegador emite uma requisição assíncrona (como o método GET) para uma URI específica do servidor.
  • Processamento: O servidor processa os cabeçalhos, rotas e parâmetros informados (filtros por nome, status, espécie ou número de página) e gera o conjunto de resultados.
  • Resposta (Response): O servidor retorna os dados acompanhados de código de status HTTP (ex.: 200 para sucesso ou 404 para dados inexistentes).
  • Atualização Dinâmica do Cliente: O script JavaScript do cliente intercepta a resposta, processa a cadeia JSON e atualiza a interface visual sem necessidade de recarregamento total da página web (comportamento de Single Page Application).

2. Conceito de DOM Manipulation e a criação de elementos dinâmicos via JavaScript

O DOM (Document Object Model) é a representação orientada a objetos da árvore hierárquica do documento HTML. A manipulação do DOM consiste em utilizar o JavaScript para inspecionar, criar, injetar, modificar estilos e remover nós dessa árvore em tempo de execução.

A criação dinâmica de elementos diferencia interfaces estáticas das modernas aplicações ricas para a web. Ao invés de inserir marcações HTML rígidas no arquivo-fonte, a página mantém apenas nós de ancoragem (como <div id="cardsContainer"></div>). À medida que a resposta da API chega, o JavaScript instancia os elementos em memória na quantidade exata retornada pela fonte de dados, garantindo responsividade, escalabilidade e desacoplamento entre estrutura e dados.

3. Explicação das funções básicas utilizadas para consumo da API

O projeto utilizou exclusivamente os recursos nativos do padrão ECMAScript:

  • fetch(url): Método assíncrono que inicia o processo de requisição HTTP e retorna uma Promise que resolve no objeto Response assim que os cabeçalhos chegam.
  • .then(): Método encadeado que gerencia a resolução da Promise. O primeiro .then() invoca response.json() para converter o fluxo de dados em objetos JavaScript; o segundo recebe o JSON pronto e aciona a função de renderização.
  • .catch(): Captura falhas de rede, erros de resposta HTTP ou exceções internas de execução, acionando rotinas visuais de tratamento e recuperação (como telas de erro e botão de nova tentativa).
  • document.createElement(tagName): Instancia um novo nó de elemento HTML em memória com a tag informada (ex.: div, img, h3, span).
  • node.appendChild(childNode): Insere o nó filho na hierarquia do elemento pai, construindo a estrutura visual completa do card antes de adicioná-lo ao container da tela.

4. Breve explicação sobre o motivo da escolha da API

A API escolhida foi a Rick and Morty API (https://rickandmortyapi.com/). Os principais critérios de escolha foram:

  • Consonância com o Tema Proposto: Rick and Morty é uma das produções animadas mais icônicas e influentes dos anos 2000/2010, com forte apelo visual e narrativo.
  • Gratuidade e Acessibilidade: Trata-se de uma API pública, estável e livre de taxas, permitindo testes sem fricção ou dependência de chaves pagas.
  • Riqueza do Schema de Dados: Fornece atributos ideais para cartões detalhados: imagem de avatar oficial, nome, status vital, espécie, gênero, planeta de origem, localização atual e relação de episódios.
  • Recursos de Consulta: Suporta filtros por atributos e sistema nativo de paginação com metadados detalhados de total de registros e páginas.

5. Regras de acesso e documentação da API utilizada

  • Autenticação: Não exige tokens, bearer auth ou assinaturas criptográficas. Possui suporte completo a requisições CORS abertas.
  • Limites de Requisição: O servidor adota política de uso justo (~10.000 requisições diárias por IP). No projeto, foi aplicado mecanismo de debounce no campo de pesquisa para otimizar o fluxo de requisições.
  • Estrutura de Resposta: O endpoint /api/character retorna um objeto contendo a propriedade info (com count, pages, next e prev) e o vetor results com os 20 personagens da página solicitada.
